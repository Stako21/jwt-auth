# Полный релиз branches-config от 01.11.2026

Релиз объединяет опубликованную вкладку `Дії з документами` со всеми оставшимися программными доработками локальной рабочей версии.

## Состав

- ТРО: документы выполнения УП в списке и карточке, отдельные номера родительского заказа и выполнения, поиск по этим номерам, предупреждения при отмене родителя с активными выполнениями.
- Индивидуальные действия администратора в карточке ТРО: отмена на любой стадии с сохранением данных; доработка только до обработки в УП и бухгалтерских отметок. Групповые действия остаются в отдельной вкладке администратора.
- Документы: фильтр города ТРО с немедленным применением, компактное управление фильтрами на всех размерах экрана, поиск документа и адаптивные таблицы/карточки.
- Уведомления: группы `RETURN_EXCHANGE` / `TRO`, семь событий ТРО, тестовая отправка без сохранения адресата, независимые результаты каналов, сохранение первоначальных получателей и текста при повторной доставке.
- Debet: фильтры даты документа и предельной даты платежа, режим просроченной задолженности и счётчики просрочки.
- Редактируемый исходник `ИнтеграцияСтатусовТРОСПорталом_МодульОбъекта_v2.txt`. Пользователь подтвердил 01.11.2026, что обработка уже обновлена в 1С; локальная проверка Portal не заменяет проверку установленной EPF в её среде.

## Проверки

Точный состав приложения проверен в изолированной копии Git index без локального `.env`: 179 backend-тестов в 19 файлах, frontend lint и production-сборка прошли. Остаются предупреждения устаревшего Sass API и размера JavaScript-бандла. Production-сервер не изменялся.

## Развёртывание

Используйте [инструкцию PM2](update-pm2-production.md), зафиксировав SHA опубликованной ветки перед началом. На согласованной целевой БД до запуска нового API должны быть применены миграции `031`, `032`, `033`; runner пропускает ранее выполненные. Затем нужны сборка frontend и перезапуск API. Локальные записи `schema_migrations` не подтверждают состояние production.

Ручная регистрация дополняет `status-pending`, не меняет статусы и снимается после принятого свежего полного `execution_documents` snapshot. Портальный `COMPLETED` автоматически не отменяется. Физическая потеря родительского документа в УП остаётся ошибкой обработки. Текущий контракт: [интеграция ТРО](../docs/1c-tro-integration.md).

## Данные и материалы

Изменённые `client/public/Sorce` / `client/dist/Sorce`, включая удаления файлов, не входят в релиз кода и остаются локально. Production должен использовать свой `IMPORT_DIR`. Архивные журналы настройки `documentation/old-setings*.txt` также не публикуются.

Руководства `USER-GUIDE-TRO.docx` / `USER-GUIDE-TRO.pdf`, иллюстрации и отчёты предыдущих проверок сохранены как датированные материалы. Они описывают состояние на момент подготовки; для новых функций, ограничений и развёртывания приоритет имеют этот документ и текущая спецификация интеграции.
