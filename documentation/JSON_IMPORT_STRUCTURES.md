# Структуры JSON-файлов, используемых порталом

> Исторический обзор контрактов на 20.09.2026. В частности, последующая обработка индивидуальных конфликтов SalesReport изменилась: они могут пропускаться с `completed_with_warnings`, а структурные ошибки всего снимка остаются фатальными. Для текущих правил используйте `AGENTS.md`, код `api/services/loadSalesReports.js` и актуальные тесты. Упомянутые ниже локальные образцы не подтверждают состояние production-источников.

Актуально по фактическим парсерам проекта на 20.09.2026.

Примеры содержат вымышленные данные. Имена полей, регистр, вложенность и типы соответствуют текущему коду.

## Общие правила

- Кодировка: UTF-8. BOM в начале файла допустим.
- Корневой элемент почти всех файлов — массив объектов `[]`.
- Исключение: `BillOfLading.json` поддерживает как массив, так и объект с массивом в `items`.
- Имена GUID/UUID передаются строкой в формате `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.
- `SalesReport.json` проверяется строго и целиком отклоняется при структурной ошибке или конфликте.
- Остальные старые импорты чаще пропускают некорректную строку либо подставляют `null`/`0`; это не означает, что такие поля безопасно не передавать.

## 1. `Product.json`

Назначение: справочник обычных товаров и товарных групп для документов «Повернення / Обмін».

Корень: непустой массив.

```json
[
  {
    "product_id": "f9517469-fd7d-11ef-a3a3-2c44fd824137",
    "product_name": "Батон шоколадний 39 г",
    "group_id": "926cb7a7-ad1c-11df-8cbe-0022159961f2",
    "group_name": "БАТОНИ"
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `product_id` | string | обязательно | GUID/идентификатор товара 1С |
| `product_name` | string | обязательно | название товара |
| `group_id` | string | обязательно | GUID/идентификатор группы 1С |
| `group_name` | string | обязательно фактически | название группы; без пары `group_id` + `group_name` группа не создаётся |

Полный снимок синхронизирует активность: товары и группы текущего филиала, отсутствующие в новом корректном файле, деактивируются.

## 2. `TradePoint.json`

Назначение: справочники контрагентов и торговых точек.

Корень: непустой массив.

```json
[
  {
    "trade_point_id": "b4020c07-70f0-11ef-b694-d89d672c581b",
    "trade_point_name": "Магазин Велес-8",
    "contractor_id": "b4020bf8-70f0-11ef-b694-d89d672c581b",
    "contractor_name": "Черниш В.М. ФОП",
    "trade_point_address": "м. Кам'янське, бул. Незалежності, 7"
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `trade_point_id` | string | обязательно | идентификатор торговой точки 1С |
| `trade_point_name` | string | рекомендуется | название торговой точки |
| `contractor_id` | string | обязательно | идентификатор контрагента 1С |
| `contractor_name` | string | рекомендуется | название контрагента |
| `trade_point_address` | string | optional | адрес торговой точки |

Полный снимок синхронизирует активность контрагентов и торговых точек внутри текущего `branch_id`.

## 3. `Product_TRO.json`

Назначение: справочник ТРО.

Корень: непустой массив.

```json
[
  {
    "product_id": "3c3fcc36-23a0-11f1-bb23-c210c7f2a6f7",
    "product_name": "Стійка рекламна мала",
    "group_id": "c6074310-23a0-11f1-bb23-c210c7f2a6f7",
    "group_name": "СТІЙКИ"
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `product_id` | string | рекомендуется | идентификатор ТРО в 1С |
| `product_name` | string | обязательно | название ТРО; строка без названия пропускается |
| `group_id` | string | рекомендуется | идентификатор группы ТРО |
| `group_name` | string | рекомендуется | группа для фильтра и подбора ТРО |

Особенности:

- Источник глобальный, но каждая корректная позиция создаётся отдельно для каждого активного филиала.
- Уникальность исходной позиции строится по совокупности всех четырёх полей, поэтому одинаковый `product_id` с другой группой/названием не схлопывается автоматически.
- Отсутствующие в следующем полном снимке позиции деактивируются.

## 4. `SalesAgent.json`

Назначение: позиции/маршруты торговых агентов 1С и их связь с портал-пользователями.

Корень: непустой массив.

Пример одного пользователя с двумя ассортиментными позициями:

```json
[
  {
    "id": 1,
    "routeName": "UA0109091113 ТП Пилипенко Ірина",
    "routeGuid": "42b1ad92-23a0-11f1-bb23-c210c7f2a6f7",
    "login": "UA013-0095",
    "regionalDivision": "Черкаси",
    "regionalDivisionGuid": "a5658d74-efd9-11de-9660-0018de795512",
    "currentAgent": "Пилипенко Ірина Вадимівна",
    "currentAgentGuid": "6cf3fb81-77da-11ee-80e7-0050568a5bd8",
    "supervisor": "Офіс Черкаси",
    "supervisorGuid": "b99c2cf4-2b87-11ee-80d8-0050568a5bd8",
    "assortment": "MontBlanc",
    "assortmentGuid": "d3dd4f7e-3c44-11e1-ae17-002618a12e97"
  },
  {
    "id": 2,
    "routeName": "UA1302210205 ТП Пилипенко Ірина",
    "routeGuid": "42b1adba-23a0-11f1-bb23-c210c7f2a6f7",
    "login": "UA013-0059",
    "regionalDivision": "Черкаси",
    "regionalDivisionGuid": "a5658d74-efd9-11de-9660-0018de795512",
    "currentAgent": "Пилипенко Ірина Вадимівна",
    "currentAgentGuid": "6cf3fb81-77da-11ee-80e7-0050568a5bd8",
    "supervisor": "Офіс Черкаси",
    "supervisorGuid": "b99c2cf4-2b87-11ee-80d8-0050568a5bd8",
    "assortment": "Lacmi",
    "assortmentGuid": "d3dd4f7f-3c44-11e1-ae17-002618a12e97"
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `id` | number | optional | служебный номер строки; текущий импорт его не сохраняет |
| `routeName` | string | рекомендуется | название позиции/маршрута 1С |
| `routeGuid` | string | обязательно для надёжной интеграции | GUID позиции/маршрута; не должен повторяться в снимке |
| `login` | string | обязательно для импортируемой позиции | логин позиции; пустой логин означает, что строка будет проигнорирована |
| `regionalDivision` | string | рекомендуется | название города/регионального подразделения |
| `regionalDivisionGuid` | string | рекомендуется | GUID регионального подразделения |
| `currentAgent` | string | рекомендуется | ФИО текущего ТА |
| `currentAgentGuid` | string | обязательно для модели 1:N | GUID физического ТА, связывающий несколько его позиций |
| `supervisor` | string | optional | snapshot имени руководителя |
| `supervisorGuid` | string | optional | GUID руководителя |
| `assortment` | string | рекомендуется | название ассортимента позиции |
| `assortmentGuid` | string | рекомендуется | GUID ассортимента позиции |

Правила связи:

- Позиция, у которой `login` совпадает с `users.NAME`, является якорной и обновляет у пользователя `user_name` и `current_agent_guid`.
- Остальная позиция может быть привязана к тому же пользователю по совпадающему `currentAgentGuid`.
- `login` должен быть уникален в одном файле.
- Непустой `routeGuid` должен быть уникален в одном файле.
- Строки без `login` учитываются в статистике как `ignored_no_login`, но не импортируются как позиции.

## 5. `SalesReport.json` — текущий строгий контракт

Назначение: документы отчёта «Продажі».

Корень: непустой массив.

```json
[
  {
    "id": 1,
    "DocumentGuid": "f78c97b5-aaae-11f1-bb33-08f1ea7c794f",
    "currentDate": "2026-09-17T13:43:33+03:00",
    "date": "2026-09-15T08:00:00+03:00",
    "number": "СГ000000067744",
    "isDeleted": false,
    "amount": 2210.1,
    "pointOfSale": "Магазин ТПС",
    "form2": false,
    "comment": "",
    "customer": "Герасимович Н.М. ФОП",
    "salesAgentGuid": "4c5a5f6c-0714-11eb-a5cc-0cc47ab3cac1",
    "salesAgent": "Мирошниченко Юрій Вікторович",
    "agentLogins": [
      "UA013-0012"
    ]
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `DocumentGuid` | UUID string | обязательно | стабильная идентичность документа; GUID не должен повторяться в файле |
| `date` | date/datetime string | обязательно | дата документа; должна разбираться JavaScript `Date` |
| `number` | string | обязательно, non-empty | номер документа |
| `salesAgentGuid` | UUID string | обязательно | фактический GUID ТА |
| `agentLogins` | array of strings | обязательно | один или несколько логинов позиций ТА; массив может быть пустым, но тогда остаётся разрешение по GUID |
| `salesAgent` | string | optional | snapshot имени ТА |
| `amount` | number | рекомендуется | сумма документа |
| `pointOfSale` | string/null | optional | торговая точка |
| `customer` | string/null | optional | контрагент |
| `comment` | string/null | optional | комментарий |
| `form2` | boolean | optional | признак Ф2; отсутствие трактуется как `false` |
| `isDeleted` | boolean | optional | `true` отменяет документ; отсутствие трактуется как `false` |
| `id` | any | игнорируется | номер строки источника |
| `currentDate` | any | игнорируется | служебная дата формирования источника |

Важно:

- Старое поле `loginAgent` больше не является текущим контрактом вместо `agentLogins`.
- `DocumentGuid`, `salesAgentGuid` и `agentLogins` обязательны для каждой строки.
- Любой невалидный обязательный GUID, невалидная дата, не-массив `agentLogins` или повтор `DocumentGuid` приводит к контролируемому отказу всего импорта.
- Импорт хранит окно последних 35 дней; более старые строки источника отмечаются как вне окна и не импортируются.

## 6. `OrderByTimet.json`

Назначение: отчёт заявок ТА по времени.

Корень: массив.

```json
[
  {
    "date": "2026-09-20T10:35:00+03:00",
    "number": "ЗК000001234",
    "salesAgent": "Пилипенко Ірина Вадимівна",
    "supervisor": "Керівник Черкаси",
    "city": "Черкаси"
  }
]
```

Поля:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `date` | date/datetime string | обязательно | дата и время заявки; невалидная строка пропускается |
| `number` | string | рекомендуется | номер заявки |
| `orderNumber` | string | fallback | читается вместо `number`, если `number` отсутствует |
| `salesAgent` | string | optional | ТА |
| `supervisor` | string | optional | СВ |
| `city` | string | optional | город |

Данные заменяются по датам, присутствующим в источнике; срок хранения — 31 день.

## 7. `BillOfLading.json`

Назначение: отчёт собранных накладных и расчёт заработка комплектувальников.

Рекомендуемый корень — объект периода с массивом `items`:

```json
{
  "periodStart": "2026-09-19T08:00:00+03:00",
  "periodEnd": "2026-09-20T08:00:00+03:00",
  "items": [
    {
      "warehouseName": "Склад Запоріжжя",
      "warehouseGUID": "f65d6840-92fd-11e4-a77b-00155d01020b",
      "picker": "Іваненко Іван Іванович",
      "pickerGUID": "ad04d861-7cba-11ee-80e7-0050568a5bd8",
      "documentNumber": "СГ000000073125",
      "documentDate": "2026-09-19T11:15:00+03:00",
      "scanDate": "2026-09-19T14:42:18+03:00",
      "documentsCount": 1,
      "rowsCount": 12,
      "weight": 84.35,
      "amount": 15420.5
    }
  ],
  "totalRows": 1
}
```

Также поддерживается упрощённый корень-массив:

```json
[
  {
    "warehouseName": "Склад Запоріжжя",
    "warehouseGUID": "f65d6840-92fd-11e4-a77b-00155d01020b",
    "picker": "Іваненко Іван Іванович",
    "pickerGUID": "ad04d861-7cba-11ee-80e7-0050568a5bd8",
    "documentNumber": "СГ000000073125",
    "documentDate": "2026-09-19T11:15:00+03:00",
    "scanDate": "2026-09-19T14:42:18+03:00",
    "documentsCount": 1,
    "rowsCount": 12,
    "weight": 84.35,
    "amount": 15420.5
  }
]
```

Поля строки:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `scanDate` | date/datetime string | обязательно | время сканирования; определяет отчётный день 08:00–08:00 |
| `documentDate` | date/datetime string | optional | дата документа |
| `warehouseName` | string | рекомендуется | название склада |
| `warehouseGUID` | string | рекомендуется | GUID склада; используется для справочника складов |
| `picker` | string | рекомендуется | ФИО комплектувальника |
| `pickerGUID` | string | обязательно для персонального доступа | связывается с `users.user_guid` |
| `documentNumber` | string | рекомендуется | номер накладной |
| `documentsCount` | number | optional | количество документов; приводится к целому неотрицательному |
| `rowsCount` | number | optional | количество строк; приводится к целому неотрицательному |
| `weight` | number | optional | вес; невалидное значение становится `0` |
| `amount` | number | optional | сумма; невалидное значение становится `0` |

Поля оболочки:

| Поле | Тип | Требование | Использование |
|---|---|---|---|
| `periodStart` | date/datetime string | рекомендуется | позволяет очистить/заменить отчётный день даже при пустом `items` |
| `periodEnd` | date/datetime string | optional | граница выгрузки; сохраняется как metadata источника |
| `items` | array | обязательно для объектной формы | строки отчёта |
| `totalRows` | number | optional | информационное поле; парсер его не использует |

# Какие JSON-контракты изменились последними

Последнее изменение форматов выполнено 17.09.2026 в commit `f961be2` (`Normalize sales agent and sales report imports`).

## `SalesReport.json` — изменён последним и требует обновлённой выгрузки

Текущий строгий формат требует:

- `DocumentGuid` — новый обязательный стабильный GUID документа;
- `salesAgentGuid` — обязательный GUID фактического торгового агента;
- `agentLogins` — обязательный массив логинов позиций вместо старого одиночного `loginAgent`;
- `isDeleted` используется для отмены документа;
- повтор `DocumentGuid` внутри одного файла запрещён.

Важно: файл `client/public/Sorce/SalesReport.json`, находящийся в рабочем дереве на момент проверки, всё ещё имеет старую структуру (`loginAgent`, без `DocumentGuid`, `salesAgentGuid`, `agentLogins`) и не соответствует текущему строгому парсеру. Актуальный образец `D:\projects\TEMP\SalesReport.json` соответствует новому контракту.

## `SalesAgent.json` — изменена модель строк и добавлен ассортимент

Последняя версия контракта используется как снимок позиций 1С:

- один портал-пользователь может иметь несколько строк/позиций;
- якорная позиция находится по `login = users.NAME`;
- дополнительные позиции связываются с тем же пользователем по `currentAgentGuid`;
- добавлены и сохраняются `assortment` и `assortmentGuid`;
- `routeGuid` и `login` должны быть уникальны среди импортируемых строк;
- строки с пустым `login` теперь явно игнорируются, а не создают позицию.

## Более ранние изменения

- `Product_TRO.json` добавлен вместе со справочником ТРО 28.08.2026; текущая структура с `product_id`, `product_name`, `group_id`, `group_name` после этого не менялась.
- `BillOfLading.json` ранее был дополнен `warehouseGUID` и `pickerGUID`, а также объектной оболочкой периода с `items`; это изменение старше текущих контрактов `SalesAgent.json`/`SalesReport.json`.
- `Product.json`, `TradePoint.json`, `OrderByTimet.json`, `report_romashka.json` и `DebetReport.json` в последней фазе импорта структурно не менялись.
